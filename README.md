# 耗电模式 v0.1.7

[打开页面](docs/index.html)。GitHub Pages 发布目录为 `/docs`。界面保留磨砂玻璃圆形按钮（三角开始／方形停止）、运行计时和底部版本号。背景使用 stackedlol/ascii-sharks 的原始固定网格、字符色块、鱼群和鲨鱼游动逻辑，适配系统浅色／深色模式。页面打开后鲨鱼即持续游动，停止耗电后也继续游动；点击开始才运行耗电负载，停止时冻结计时，下一次开始重新计时。页面隐藏或离开时暂停动画，回到前台后恢复；遵循系统“减少动态效果”设置。

本版的方向是提高每次数据访问对应的计算量，减少等待内存和频繁同步；不把线程数、卡顿或 CPU 占用直接等同于整颗芯片满载。

v0.1.3 修复移动 Safari 拖动时的画面跳变：页面固定在视口内，按钮使用明确的等宽高和独立的圆形模糊裁切层；视口变化保留原鱼群及模拟进度，不重新随机生成。仅轻点水面触发涟漪，拖动或取消触摸不会触发。

v0.1.4 将拖动限制在前景：按钮、计时和版本号带阻尼跟随手势，松手回位；网格与鱼群不随拖动平移，鲨鱼照常游动。拖动按钮不会误启动／停止负载；计时下方增加向外渐隐的模糊背景，数字保持清晰。圆形按钮降低底色和高光的不透明度，并稍减模糊，让背景更透出来。切后台或离开时清除拖动状态，系统“减少动态效果”开启时关闭拖动动画。

| 负载 | 实际任务与 v0.1.1 改动 | 能力边界 |
| --- | --- | --- |
| CPU 整数／浮点 SIMD | 独立 Worker 运行内嵌 Wasm SIMD128：浮点使用 8 组独立四通道乘加链，整数使用 4 组独立四通道乘法／移位／异或链。循环内不读写线性内存，结果汇总后上报 | 可减少数据搬运和单一依赖链，不能保证特定硬件执行单元满载；不支持 SIMD 时回退 JavaScript |
| CPU 浮点 | 保留独立 Worker 持续进行 sin、cos、sqrt 和浮点乘除 | 由 JavaScript 引擎决定执行方式 |
| CPU 矩阵 | 128×128 矩阵点积，转置右矩阵后连续读取，保留多个独立累加器 | 提高局部性，不等于调用 CPU 专用机器学习硬件 |
| 内存 | 单独保留 1 个 Worker，两块各 4 MiB 数组顺序复制、变换；取消随机大跨步访问，并在复制间执行寄存器内整数运算 | 不再将四分之一 CPU 线程用于内存任务，避免其大量争抢带宽；不进行磁盘交换或无限分配 |
| GPU | 保留 16 MiB 数据、每个元素 512 次迭代、每轮 4 次全量扫描与全分辨率渲染；计算拆成最多 262,144 个元素、渲染拆成最多 512×512 像素的批次，最多十六批在途，每四批设一个完成检查点，检查点完成后补充四批；在原三角函数内核中增加 8 组独立向量乘加链，重复利用已读入的数据，不增加存储缓冲区读写；Raymarch 每像素执行 192 步和每步 16 次分形迭代，命中或走出场景后不提前结束；使用独立 GPU 纹理保存渲染结果并由计算着色器采样 | WebGPU 不可用时回退 WebGL2 仅渲染；不能读取真实 GPU 利用率 |
| 视频 | 本地合成高细节的动态 1080p 画面进行 H.264 编码／解码；队列满时反压编码，不再在 decoder.flush 时跳过编码帧；使用 MessageChannel 补充任务，避免 setTimeout 的调度间隙 | 限制在途帧／解码队列；请求 prefer-hardware，具体设备由浏览器决定 |
| 加密 | 对复用的 1 MiB 数据，保持两组 AES-256-GCM 与 SHA-256 操作并行；每次加密使用不同 IV | 缩小工作集、限制并发量；Web Crypto 不代表 Secure Enclave 负载 |
| 神经网络 | WebNN 可用时执行四层 512×512 矩阵乘法＋ReLU，在最后一层后才读回结果，降低每层读回造成的同步占比 | 高性能加速由浏览器分配到 CPU、GPU 或 NPU，不能保证 Neural Engine 被调用 |

CPU 计算 Worker 数为浏览器报告并发数的两倍，最少 4、最多 64，在 SIMD 整数、SIMD 浮点、三角函数浮点和矩阵之间分配；额外启动 1 个内存、1 个加密、1 个视频 Worker。不支持的可选接口会跳过，在控制台诊断中注明。

不使用摄像头或麦克风，不加载 ISP；不声明覆盖 Secure Enclave 等没有通用网页压测接口的单元。不上传或保存计算／视频数据，不下载模型，不持续写磁盘，不使用 HDR。

开始时请求屏幕唤醒锁；停止、切后台或离开页面时终止 Worker、销毁 GPU/WebNN 资源、取消负载调度和定时器并释放唤醒锁。初始化或唤醒请求延迟返回时也会清理。返回前台只恢复鲨鱼动画，不会自动继续耗电负载。待机仅运行背景动画，不申请唤醒锁，不改变系统自动锁屏设置。WebGPU 运行异常时保留 CPU、其他独立任务和计时，尝试重建一次；再次失败回退 WebGL2，后者也失效则仅保留其他任务；回退后以 30、60、120 秒的间隔最多再尝试三次恢复 WebGPU，不无限重试。停止、切后台或离开会取消恢复；旧设备的延迟回调不能影响新任务。

控制台 `window.burnDiagnostics` 可查看页面可见性、计时时长、各任务运行／跳过／失败状态及完成进度。CPU Dasher 等外部测量应在 Safari 仍可见且负载仍在运行时比较；本版功能测试不代表已经在真实 iPad 上确认 CPU 100% 或更快掉电。

v0.1.5 针对升级 iPadOS 27.2 后报告的拖影和负载中断：移除背景缓存画布，每帧直接填满底色并重画固定网格；2D 画布丢失时暂停动画调度，恢复后重建绘制状态，保留鱼群和模拟时间。GPU 采用上述小批次连续提交与有限恢复。未改 CPU 计算强度、背景像素密度、按钮或计时样式。故障注入能在 v0.1.4 复现缓存失效后的残影，但不代表已确认 iPadOS 27.2 的底层触发原因。

v0.1.6 为持续耗电扩大 GPU 批次：单批计算元素和渲染像素均为 v0.1.5 的四倍，在途上限从两批增至八批。每四批设完成检查点，检查点完成时补充队列，其后已有四批可供 GPU 继续执行；不再逐批等待 JavaScript 回调。计算内容、每轮扫描覆盖和有限异常恢复保留。控制台增加已完成计算元素、渲染像素和完成回调数，便于按单位时间比较；这些数值不是功耗或真实利用率。

v0.1.7 针对 v0.1.6 实机反馈耗电变慢：移除 Raymarch 命中／越界提前退出，向量乘加链由四组增加为八组；渲染改写独立 GPU 纹理，计算阶段定期采样其结果，全部留在 GPU 内。队列上限从八批增至十六批，为主线程繁忙时提供更多待执行工作。轻负载回退后新增有次数上限和退避间隔的 WebGPU 恢复，停止／切后台／离开会取消重试。以上改动需要在 iPad 上复测实际掉电时间，不能据此保证恢复到半小时耗尽。

## 开发与构建

网页为静态文件，不需要 npm 安装或服务端。构建使用本机 Node.js（需支持 `node:module.stripTypeScriptTypes`）和支持 wasm32／SIMD128 的 Clang：

```sh
node scripts/build-simd.cjs
node scripts/build-ocean.cjs
```

- SIMD 源码为 `src/burn-simd.c`。构建脚本会编译、验证两个内核并内嵌进 `docs/index.html`，不需要单独下载 Wasm，不需要链接器或额外依赖。
- 鲨鱼原始源码保存在 `vendor/ascii-sharks/`；来源与固定 revision 见该目录的 `UPSTREAM.md`。`src/ocean-controller.js` 负责页面启停、20 FPS 绘制调度和输入适配；`src/foreground-controller.js` 负责前景手势，两者一起构建到 `docs/ocean.js`，不要手改生成文件。

## 分支与版本

- 直接在 `main` 开发和推送，GitHub Pages 从 `/docs` 发布；默认不创建其他分支。
- 已定版的提交和标签固定保留。每个开发周期只维护一个滚动提交，后续修改通过 amend 覆盖，并使用 `--force-with-lease` 推送。
- 当前周期从 `v0.1.1` 开始，补丁版本依次递增；明确要求发布 `v0.2.0` 时才固定提交并打标签，之后从 `v0.2.1` 开启下一周期。
- 网页迭代同步标题、页脚、脚本版本参数与 README；纯文档修改不递增网页版本。AI 操作细则见 [AGENTS.md](AGENTS.md)。

## 回归检查

- `node tests/gpu-lifecycle.cjs`：模拟设备丢失，检查计算／像素覆盖、在途上限、提前补充与检查点去重、重建、旧回调隔离、停止重启竞争和离开时清理。它不测硬件性能。
- 用本地静态服务器打开 `tests/ocean-rendering.html`：真实 Canvas 像素检查、模拟 contextlost/contextrestored、确认动画恢复和暂停状态。无须安装测试依赖。
- 真实 GPU 运行和 iPad 实机问题需另外验证；注入事件不能代替真实驱动重置。
